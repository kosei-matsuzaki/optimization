### 2026-09-08（ユーザー決定）— 案 (C): MC-ESO の調律をやめ、クラスの外に出る手法を作る

[status.md](status.md) の「ユーザーの判断を仰ぐこと (1)」への回答。**案 (C) を採る。**
ゴール（多峰度の高い問題で、既存手法より多くの大域最適を見つける）は**変えない**。
外すのは手法側の制約で、**今後 MC-ESO の変種を新しく作らない**（既定値も不変、比較対象としては残す）。

**理由**: その88・その89 が閉じたのは MC-ESO の 1 構成ではなく**クラス**だった ——
「一様再起動 ＋ 局所降下」の被覆上限が **F14-F20 の 7 関数すべてで公表最良 `PR@1e-5` を下回る**。
MC-ESO はこのクラスの中にいるので、**どの腕を足しても上限の側から勝てない**。勝つにはクラスの外に出るしかない。
85 サイクルすべてが MC-ESO の変種だったのはゴール文の制約ではなく惰性なので、そこを外す。

### 2026-09-08（ユーザー決定・最優先）— GECCO 2024/2025 の新 suite を導入し、まずクラス上限を引き直す

**この項目は下の 2 件および「未解決の問い」のすべてに優先する。**

**事実**: [related_work.md](related_work.md) が 2026-08-30 に既に記録している ——
**GECCO 2024/2025 の competition は CEC2013 から Ahrari+ の新 suite（16 問、fully scalable / tunable な
composite 問題）に移行済み**で、その suite は **"designed to address some drawbacks of the well-known
CEC'2013 test suite"** と明示されている（[GECCO 2024 競技](https://sites.google.com/view/evopt/projects/gecco2024-mmo)、
[実験設定](https://dl.acm.org/doi/10.1145/3638530.3664055)、[GECCO 2025 も同 suite で継続](https://gecco-2025.sigevo.org/Competition?itemId=2783)）。
移行の理由は**飽和**で、CEC2013 は上位手法が PR 0.85 前後で頭打ちになっている。
**この事実は 1 年近く記録にありながら、90 サイクル一度も行動に移されていない。**

**なぜ最優先か（2 つ、後者が重い）:**

1. **投稿先は GECCO**（キュー 5）。その GECCO 自身が引退させた suite だけで評価した論文になる。

   **CF3 の最適解 {2,3} が一様抽出＋局所降下では何次元でも引けない**（32,000 本で 0 本）という測定だった。
   これは**手法の一族の性質**として書かれているが、**CEC2013 の合成関数の性質**でもあり得る
   （その88 §4 自身が「合成規則は未確認」と注記している）。**tunable に作られた新 suite では
   この上限がそもそも存在しない可能性がある。** ＝ **「MC-ESO をやめて一族の外に出る」という判断が、
   引退した飽和 suite で測った天井に依拠している。**

**やること（この順で）:**

1. **suite を取得して回せるようにする。** **`ioh` には入っていない**（`ioh.problem` は CEC2013 / CEC2022 まで。
   2026-09-08 に確認済み）ので、[配布ページ](https://sites.google.com/view/evopt/projects/gecco2024-mmo) の

### 2026-09-08（ユーザー決定・追記）— 新規性の基準と、使う指標

**(1) 新規性は「組み合わせ」で見る。個々の発想が既存でも、その組み合わせの先行研究が無ければ問題ない。**

この研究は先行研究への撤退を 7 件記録しているが、**その一部は基準が厳しすぎた**。
今後は次で判定する:

- **個々の部品が既存であること自体は撤退理由にならない。** 撤退するのは
  **その組み合わせが先行研究に存在するとき**、および **概念ではなく具体的な手続きが一致するとき**だけ。
- **「概念そのものは教科書事項だから主張できない」という理由での撤退はしない。**
  深さと広さのトレードオフ、相対的な打ち切り閾値、多様性対収束 —— いずれも枠組みとしては既存だが、
  **その組み合わせと、それがこの問題設定で何をするかは別の主張**である。
- **先行調査は引き続き実装前に行う**（手順 3 の鉄則、4 分野以上）。変わったのは撤退の閾値であって、
  調べる義務ではない。調べた結果は「占有されている領域」に記録し、
  **どこが一致してどこが一致しないかを書く**（「隣接分野に似た話がある」では撤退理由にならない）。

**この基準で再開してよい路線が 2 件ある**（どちらも**測定されないまま、先行研究の存在だけを理由に閉じられた**）:

- **4 件目（多スタートで観測された極小から未発見数を推定する。Chao1 / Good-Turing 系）** —— 「実装しないこと」と
  書かれているが、根拠は Boender & Rinnooy Kan 1987 / STADS の存在のみで、**この設定で効くかは一度も測っていない。**
- **5 件目（盆地ごとに予算を配分する）** —— 「三方から挟まれている」が**直接一致は未発見**と自ら書いており、
  やはり未測定。追加語彙（QD の archive 予算配分 / successive halving）を潰したうえで測ってよい。

**逆に、再開しない路線を明示する。** 上の緩和は**先行研究を理由に閉じた路線にだけ効く**。
**測定を理由に閉じた路線は閉じたまま**で、新規性の基準とは無関係:
反発半径の適応（その22）、位相分けの受理規則（その29）、σ の局所盆地間隔スケーリング（その26・その27）、
報告規則の全手法適用（その28）、`basin_reset`（その79 —— **20000 評価で pin の SR@1e-10 が 0.9625 → 0.9604 に下がる**）、
案 (A) の F14-F20（その85〜その89 のクラス上限）。**これらは「新規性が無い」から閉じたのではなく「効かない／代金が高い」から閉じた。**

**(2) 指標は分野で広く使われているものを使う。自作の指標で判定しない。**

- **判定は CEC2013 公式の peak ratio**（`cec_pr_*`、`how_many_goptima` と同順序）**で行う。**
  補助として SR@1e-10 / `evals_succ_mean` / Wilcoxon（α=0.05）＋ A12 効果量。これらは分野標準。
- **`PRtrue`（最近傍帰属で数え直した PR）は自作の診断値。計器としてだけ使い、判定の主指標にしない。**
  論文に出すときは「公式測度は ρ 依存で、この関数では同一盆地内の点を別 niche と数える」という
  **測度の性質の説明として**出す（その76）。
- **判定水準は ε ≤ 1e-3**（その28）。1e-1 は参考値として併記してよいが順位の根拠にしない。
- **公表値と比べるときは条件を揃える**（その71）: 正規予算（2e5 / 4e5）・1e-5 単独・関数番号の D と K が一致すること。
  **N05-SixHumpCamel は探索域を公式の非対称ボックスから広げてあるので公表値と直接比較しない**
  （体積が公式の 1.7 倍。`docs/experiments.md`）。
- **UI の指標表示が定義と食い違っている**（問い 3）: `web/` は履歴ベースの `pr_1e-4` を「PR」と表示しているが、
  本テーマの主指標は報告集合ベースの `cec_pr_*`。**由来が分かる列名に直すこと。**

**この方針の下での順序:**

1. **まず問い 2（hill-valley 判定つきの desc null）を最優先で回す。** 案 (C) の下では、これは

   **これでクラス上限が動くなら新手法はそこに載せる。動かないなら「降下ベースの被覆」自体が
   この関数集合の上限なので、機序はもっと遠くから持ってくる。** どちらに転んでも次が決まる。
2. **実装の前に必ず先行調査**（手順 3 の鉄則、4 分野以上の語彙）。**この研究は既に 7 件を

3. **新しい機序も新しい対象集合も、安いスクリーンを先に通す**（status.md の (A2) に書かれた規則を

4. **滞留している採用判断 6 件は、もう「勝つ道具の候補」ではない。** ゴールの帰趨と切り離し、

5. **俯瞰へ**: 次の回でキューを案 (C) に向け直すこと。問い 3-5（UI / 出典 / 片付け）は残してよいが、

## この研究のゴール（毎回、着手する問いをここに照らすこと）

**多峰度の高い問題（大域最適が多い問題）で、既存手法より多くの大域最適を見つける。**

分野の系統的レビュー（[Algorithms 17(10):448, 2024](https://doi.org/10.3390/a17100448)）が
未解決課題として「次元と多峰度が高いときのスケーラビリティ」を挙げ、今後の方向として
"space and time-scalable methods" を名指ししている。実測でも headroom はここに集中する:
K=36 の N07 では最良手法が PR 0.97 に届くのに、K=216 の N09 では 0.49、他手法はほぼ 0.25 未満。

- **主指標**: CEC2013 niching の peak ratio（精度 ε = 1e-1 〜 1e-5）。**特に K の大きい関数**
  （N06 K=18 / N07 K=36 / N08 K=81 / N09 K=216）。
  **ただし手法の判定は ε ≤ 1e-3 で行う**（その28）。1e-1 は報告規則の質を測っており、
  報告規則を揃えると 7 手法中 7 手法が N07 で 1.00 に張り付いて識別力を失う。
  1e-1 / 1e-2 は参考値として併記してよいが、順位の根拠にしない。
- **この研究における「多様性」の定義**: 精度 ε 以内で発見された相異なる大域最適の数。
  分野の標準定義を採り、自作の定義は使わない。
- **比較対象**: NMMSO / NCDE / Crowding-DE / r3pso / NM-Restart / MC-ESO。現状の首位は NMMSO。
- **手法は自由**。MC-ESO を改善する必要はない。比較対象の 1 つとして残すだけ。
  ただし MC-ESO 自体を壊さない（BBOB-24 dim2 の SR@1e-10 93.5% は既存資産として保つ）。

**問いを選ぶときの条件**: その問いが片付くと、K の大きい関数の peak ratio が上がるか、
上がらない方向を確実に潰せるか。どちらでもない問いは、面白くても後回しにする。

**占有されている領域**（実装前に必ず確認したこと）:

- **報告規則を独立した設計対象にすること**は済み。[Peak Identification in Evolutionary
  Multimodal Optimization](https://pmc.ncbi.nlm.nih.gov/articles/PMC11505590/) が探索と選別を
  2 相に分け、niche 半径不要の HVPI と冗長解を罰する F 値を提案している。
- **報告効率を測ること**も済み。GECCO competition の Dynamic F1（報告解のうち相異なる
  大域最適だった割合の、評価回数に沿った積分）。
- **持続性による盆地分解**は [arXiv 2605.18351](https://arxiv.org/pdf/2605.18351) が占有。
- **盆地ごとに局所スケールした step-size で再起動を蒔くこと**は
  **[MSC-CMA-ES, arXiv 2606.15830](https://arxiv.org/html/2606.15830)** が占有（nearest-better clustering で
  盆地を同定し、盆地ごとに step-size と population を局所スケールして再起動）。
  ＝ **その23 の σ 路線は、3D で畳んでいなくても手法としては新規でなかった**（2026-09-03 の俯瞰で判明）。
- **冗長な再起動の回避（同じ盆地に戻らない）**は
  [arXiv 2405.01226 / PPSN 2024](https://arxiv.org/pdf/2405.01226) が占有 ＝ その22 の反発路線。
- **盆地サイズの推定を最適化に使うこと**は
  [GECCO 2013 ABEGA](http://www.cmap.polytechnique.fr/~nikolaus.hansen/proceedings/2013/GECCO/companion/p131.pdf) が占有。
- **「選抜が広い盆地に偏る」という現象の指摘**は
  [Information 16(7):583 (2026)](https://doi.org/10.3390/info16070583) がメタ分析済み
  ＝ **その22 が実測した現象そのものは新規性にならない。直す仕組みだけが残っている。**
- **隣接分野の確認（統計物理）**: Wang-Landau / flat-histogram（訪問済み領域を罰して訪問回数を平坦化）は
  多峰分布のサンプリングでは標準だが、**MC-ESO では描画段が既に N07 の 36 解全部を覆っており律速でない**
  （その22）ので、この機序を持ち込んでも効かない。**実装しないこと**（2026-09-03 の俯瞰で確認）。
- **隣接分野の確認（数値最適化の停止規則）**: **「多スタート法の局所探索の打ち切り閾値をスケールに対して
  相対に取る」は数値最適化の一般作法**（`FunctionTolerance` を相対で持つソルバ、多スタートの停止規則の
  古典研究 [Math. Prog. 57 (1992)](https://link.springer.com/article/10.1007/BF01581094)）。
  **採用候補（`hunt_level_tol` の eps 相対化）と一致する先行論文は見つからなかったが、
  「相対許容誤差にせよ」自体が教科書的作法である以上、これを新規性として主張してはいけない。**
  主張できるのは「niching の PR がこの調律だけで崖を作る」という**実測**の側だけ
  （2026-09-04 の俯瞰で確認。EC / niching / QD / ロバスト最適化 / 数値最適化の 5 語彙で検索）。
- **「予算で順位が変わる」ことの指摘と測り方は占有**（2026-09-05 の俯瞰で確認）。
  **moving peak ratio / moving success rate**（予算の消費に沿って「どれだけ速く確実に大域最適に届くか」を測る指標）と、
  **budget-dependent statistical ranking**（予算ごとに Friedman 順位 → Wilcoxon → Holm-Bonferroni）が既にある。
  ＝ **その50 の「1/10 予算の順位は正規予算に外挿できない」は運用規則としては正しいが、
  方法論の新規性としては主張できない。**
- **「多スタートで観測された極小を多項分布の標本と見て、未発見の個数や停止時刻を推定する」は 1987 年から占有**
  （[Boender & Rinnooy Kan, *Bayesian stopping rules for multistart global optimization methods*,
  Math. Prog. 37 (1987)](https://link.springer.com/article/10.1007/BF02591684)）。

- **その分解は「commit は無条件に足せる」を意味しない**（その41）。**深さ律速の 2 関数**

  **＝ commit も結局「関数依存」側の道具で、無条件の梃子は今のところ 1 つも無い。**
- **その組み合わせ損は用量反応で確認され、commit の路線は深さ律速側で閉じた**（その42）。

## 1 サイクルの手順

**このループは 6 時間ごとに走る**（00:29 / 06:29 / 12:29 / 18:29 UTC）。1 回 40 分以内に収める規則なので通常は重ならないが、前の回が落ちて claim が残っている場合があるので、手順 0 と 1 は飛ばさない（2 時間以上前の claim は奪ってよい ＝ 6 時間間隔なら落ちた回の claim は必ず次の回で回収される）。

0. **ブランチを合わせる** — `git fetch origin && git checkout research-loop && git pull --rebase origin research-loop`（無ければ main から作る）。**成果は全部この 1 本に積む。** 実行ごとにブランチを切らない。切ると前回の続きから進めなくなり、統合されない成果物が散る。main には触らない（人がマージする）。
1. **問いを 1 つ claim する** — 「未解決の問い」の上から、まだ claim されていないものを 1 つ選び、その行に `(claimed YYYY-MM-DD HH:MM UTC)` と書いて**即コミット・push する**。これで他の回は別の問いを選ぶ。**2 時間以上前の claim は放棄されたものとみなして奪ってよい**（奪ったら時刻を書き換える）。
2. **統合の回かを判定する** — 「作業ログ」の件数が **8 件を超えていたら、新しい実験をせずに統合作業をする**。すなわち: ログの結論を `acceptance_topology.md` の該当節に集約し、決着した問いを「未解決の問い」から消し、ログを直近 3 件＋要約に畳む。積み上がらない一番の原因は記録が増えるだけで整理されないことなので、これは実験より優先する。
3. **先行研究を潰す** — 実装の前に、隣接分野の語彙で検索する（下記「先行調査の鉄則」）。既にあるなら問いを畳んで記録し、次の問いへ。
4. **設計する** — 何を測れば白黒つくか、どういう結果なら仮説が否定されるかを先に書く。撤退条件のない実験はしない。
5. **実装して回す** — 小さく回して配線を確認してから本測定。既存スクリプトで足りるなら新規作成しない。**1 回の計算は 40 分以内**に収める。収まらないなら関数か seed を削り、削ったと書く。
6. **分析する** — 対応のある検定と効果量、seed 方向一致率。平均だけで結論を出さない。
7. **記録してコミットする** — 「作業ログ」に追記し、claim を外して結果を書く（決着したら問いを消す、続きがあれば次の問いとして書く）。**否定的結果も機序つきで残す**。**回した測定のコスト行を [1 サイクルの実績の表](acceptance_topology.md#1-run-の実測コスト40-分枠の計画はここから引くその32その37-の実測)に自分で 1 行足す**（構成・並列数・壁時計。**ログは畳まれるので、集約先の表に無いコストは次の統合で消える** —— その90 が 6 件、その96 が 4 件を後から補った。**測定ゼロの回も「run ゼロで何分かかったか」を足す**）。`research-loop` に push する。push が競合したら `git pull --rebase` して再試行。

**1 回で全部やろうとしない。** claim した問いが 40 分で終わらないと分かったら、そこまでの結果と「次はここから」をログに書いて終える。中途半端な状態を残すより、次の回が続きから入れる形にすることが優先。
