## この研究のゴール（毎回、着手する問いをここに照らすこと）

**多峰度の高い問題（大域最適が多い問題）で、既存手法より多くの大域最適を見つける。**

分野の系統的レビュー（[Algorithms 17(10):448, 2024](https://doi.org/10.3390/a17100448)）が
未解決課題として「次元と多峰度が高いときのスケーラビリティ」を挙げ、今後の方向として
"space and time-scalable methods" を名指ししている。実測でも headroom はここに集中する:
K=36 の N07 では最良手法が PR 0.97 に届くのに、K=216 の N09 では 0.49、他手法はほぼ 0.25 未満。

- **主指標**: CEC2013 niching の peak ratio（精度 ε = 1e-1 〜 1e-5）。**特に K の大きい関数**
  （N06 K=18 / N07 K=36 / N08 K=81 / N09 K=216）。
  **ただし手法の判定は ε ≤ 1e-3 で行う**（その28）。1e-1 は報告規則の質を測っており、
  報告規則を揃えると 7 手法中 7 手法が N07 で 1.00 に張り付いて識別力を失う。
  1e-1 / 1e-2 は参考値として併記してよいが、順位の根拠にしない。
- **この研究における「多様性」の定義**: 精度 ε 以内で発見された相異なる大域最適の数。
  分野の標準定義を採り、自作の定義は使わない。
- **比較対象**: NMMSO / NCDE / Crowding-DE / r3pso / NM-Restart / MC-ESO。現状の首位は NMMSO。
- **手法は自由**。MC-ESO を改善する必要はない。比較対象の 1 つとして残すだけ。
  ただし MC-ESO 自体を壊さない（BBOB-24 dim2 の SR@1e-10 93.5% は既存資産として保つ）。

**問いを選ぶときの条件**: その問いが片付くと、K の大きい関数の peak ratio が上がるか、
上がらない方向を確実に潰せるか。どちらでもない問いは、面白くても後回しにする。

**占有されている領域**（実装前に必ず確認したこと）:

- **報告規則を独立した設計対象にすること**は済み。[Peak Identification in Evolutionary
  Multimodal Optimization](https://pmc.ncbi.nlm.nih.gov/articles/PMC11505590/) が探索と選別を
  2 相に分け、niche 半径不要の HVPI と冗長解を罰する F 値を提案している。
- **報告効率を測ること**も済み。GECCO competition の Dynamic F1（報告解のうち相異なる
  大域最適だった割合の、評価回数に沿った積分）。
- **持続性による盆地分解**は [arXiv 2605.18351](https://arxiv.org/pdf/2605.18351) が占有。
- **盆地ごとに局所スケールした step-size で再起動を蒔くこと**は
  **[MSC-CMA-ES, arXiv 2606.15830](https://arxiv.org/html/2606.15830)** が占有（nearest-better clustering で
  盆地を同定し、盆地ごとに step-size と population を局所スケールして再起動）。
  ＝ **その23 の σ 路線は、3D で畳んでいなくても手法としては新規でなかった**（2026-09-03 の俯瞰で判明）。
- **冗長な再起動の回避（同じ盆地に戻らない）**は
  [arXiv 2405.01226 / PPSN 2024](https://arxiv.org/pdf/2405.01226) が占有 ＝ その22 の反発路線。
- **盆地サイズの推定を最適化に使うこと**は
  [GECCO 2013 ABEGA](http://www.cmap.polytechnique.fr/~nikolaus.hansen/proceedings/2013/GECCO/companion/p131.pdf) が占有。
- **「選抜が広い盆地に偏る」という現象の指摘**は
  [Information 16(7):583 (2026)](https://doi.org/10.3390/info16070583) がメタ分析済み
  ＝ **その22 が実測した現象そのものは新規性にならない。直す仕組みだけが残っている。**
- **隣接分野の確認（統計物理）**: Wang-Landau / flat-histogram（訪問済み領域を罰して訪問回数を平坦化）は
  多峰分布のサンプリングでは標準だが、**MC-ESO では描画段が既に N07 の 36 解全部を覆っており律速でない**
  （その22）ので、この機序を持ち込んでも効かない。**実装しないこと**（2026-09-03 の俯瞰で確認）。
- **隣接分野の確認（数値最適化の停止規則）**: **「多スタート法の局所探索の打ち切り閾値をスケールに対して
  相対に取る」は数値最適化の一般作法**（`FunctionTolerance` を相対で持つソルバ、多スタートの停止規則の
  古典研究 [Math. Prog. 57 (1992)](https://link.springer.com/article/10.1007/BF01581094)）。
  **採用候補（`hunt_level_tol` の eps 相対化）と一致する先行論文は見つからなかったが、
  「相対許容誤差にせよ」自体が教科書的作法である以上、これを新規性として主張してはいけない。**
  主張できるのは「niching の PR がこの調律だけで崖を作る」という**実測**の側だけ
  （2026-09-04 の俯瞰で確認。EC / niching / QD / ロバスト最適化 / 数値最適化の 5 語彙で検索）。
- **未占有の可能性がある領域（2026-09-04 の俯瞰で確認）**: **CEC2013 の合成関数 F11-F20（5D/10D/20D）には
  headroom が実在する。** 文献側が **F18/F19（10D）と F20（20D）は効率的に解けていない**と明記している
  （[RLEMMO, arXiv 2404.08242](https://arxiv.org/pdf/2404.08242)、
  [arXiv 2511.17571](https://arxiv.org/pdf/2511.17571)）。
  **いま登録しているのは 2D/3D の易しい側（N04-N10）だけ**で、その50 の正規予算測定では
  NMMSO がその 7 関数を全部解いている（最小 0.984）＝ **現在の関数集合にゴールの余地は無い。**
  対象集合を変えるかはユーザーの判断（`status.md` に提案として置いた）。

**分かっている手がかり**（過去の測定から。**数値・表・機序の全文は
[acceptance_topology.md の「多峰テーマ（peak ratio）の確定事項」](acceptance_topology.md#多峰テーマpeak-ratioの確定事項)**
にある。ここは見出しだけ）:

- **受理規則が深さと広さを同時に決めている。** 親比較なら深さ、最近傍置換なら広さ。
  1 つのつまみでは両立しない（MC-ESO で SR@1e-10 100% → 0%、DE / PSO でも同傾向）。
- **効くのは返す個数ではなく、上位が互いに別物であること。**
- **MC-ESO はどちらの地形でも「盆地は見つけるが掘り切らない」**（その20 で統一された）。
  Shubert は PR@1e-1 0.80 → PR@1e-5 0.15。Vincent は報告規則のせいで見えにくかっただけで、
  履歴を見れば N09 の 216 個すべてに 1e-1 まで近づいており、1e-3 まで降りるのは約 28 個。
  **かつて「Vincent はそもそも見つけない」と書いていたのは誤り**（報告集合しか見ていなかった）。
- **hunt 単位で見ると `reported ≈ min(distinct hunts, deep hunts)`**（その21）。
  **Vincent は distinct（被覆）側、Shubert は deep（深さ）側が binding。**
  Vincent には局所最適が存在しないので、盆地に入りさえすれば必ず降り切る。
- **PR は evals/K でも K でも決まらない**（その17）。分けているのは
  **予算を新しい最適解に変換し続けられるか**。r3pso は完全に飽和、MC-ESO は高 K でだけ飽和、
  NMMSO だけが高 K でも変換し続ける。
- **報告枠は制約になっていない**（その19・その20）。採点上限 max(100, 2K) に対し
  MC-ESO は 88 点しか報告していないが、履歴から選び直しても利得は **eps=1e-1 に集中**する。
  1e-3 以下では実質同等なので、**報告規則側の残り代は浅い**。
- **報告規則の路線は 7 手法で測って閉じた**（その28）。選び直しを全手法に与えると
  利得は**全手法で eps=1e-1 に集中**し（N07 は 7/7 手法が PR@1e-1 = 1.00 に張り付く）、
  **eps ≤ 1e-3 では上位 2 位が全 5 関数で一切動かない**。
  **NMMSO が最も利得を受けない手法**なので、この路線で首位との差は埋まらない。
  → **運用規則: PR@1e-1 で手法を比較しない。判定は 1e-3 以下で行う**（下記）。
- **再起動の被覆を決めているのは描画ではなく選抜**（その22）。盆地切替は 20 スロット全部を
  独立に反発描画するので描画は全 36 解を覆うが、μ+λ 貪欲の best-of-20 が系統的に広い盆地の
  点を選ぶため着地は 11-15 解に留まる。**描画規則や σ_init（箱に対する固定比）を変えても
  この偏りは動かない。**
- **`sigma_only` の利得は hunt 数ではない**（その25）。予算を 40% 増やして hunt 数を
  追い越させた base（51.5 対 49.1）でも N07 の PR@1e-3 は届かず 15 seed 全敗。
  ただし **σ と予算は別の精度水準に効く**（Shubert の粗い水準は予算律速で σ は動かさない）。
  **解放規則（`hunt_no_improve_mult` / `exhausted_sigma_tol`）では base の hunt 数は上がらない。**
- **ただし「σ を局所盆地間隔に合わせる」は別のつまみで、これは効く**（その23）。
  再起動後の σ を `0.1 × d_local`（観測済み盆地重心の最近傍距離、追加評価ゼロ）にすると
  N07 の PR は全 eps で 0.22 → 0.34（15/15 seed）、さらに 20 本の描画を 1 本に commit すると
  0.44。着地した相異なる最適解は 11/36 → 26/36。**箱に対する比と局所盆地間隔に対する比を
  混同しないこと** — その22 が振ったのは前者、効いたのは後者。
- **しかしその利得は 2D 限定で、路線ごと畳んだ**（その26・その27）。**N08-Shubert3D では符号が反転し**
  （PR@1e-1 が base 0.34 に対し 0.20、5 seed 全敗）、**比を 0.1 / 0.25 / 0.5 と振っても
  内点に最適は無い**（全カラムが単調に base へ戻る）。**痛みが消える 0.5 は効果も消えている**
  （深精度の利得が 5 seed 全部で base と同値）。3D では深さの利得が**有償**になる
  ＝ **次元が上がると深さと広さが再結合する**。詳細は
  [acceptance_topology.md の該当節](acceptance_topology.md#局所盆地間隔スケーリングは-2d-限定で確定--3d-では比が単調なトレードオフダイヤルになるその26その27-analysishmn08_csv)。
  **BBOB-24 dim2 はこの路線に対する識別力を持たない** — 盆地が 3 個未満だと base の経路に
  落ちるので、全 24 関数で MC-ESO とビット一致する（＝安全の証拠ではなく未発火の証拠）。
- **ただし「3D で畳んだ」は対象の取り違えだった**（その39）。同じ `commit_tight` を
  **被覆律速の 3D 関数 N09-Vincent3D** に当てると **PR@1e-1 0.114 → 0.210（15/0/0）、
  PR@1e-3 0.110 → 0.148（14/1/0、p=0.0007）、visited も 25.9 → 32.1** で、**符号は反転しない**。
  **再結合は次元の性質ではなく深さ律速性の性質**で、その26・その27 が測ったのは
  「3D」ではなく「N08-Shubert3D が深さ律速であること」だった。**被覆軸は閉じていない。**
  ただし **N09 の NMMSO は PR@1e-3 = 0.460 なので、この利得は差の 1 割強しか埋めない。**
- **その `commit_tight` は 2 成分に分解でき、片方は深さを払わない**（その40）。同じ比 0.1 で
  2×2 に開くと、**(i) commit（best-of-n_pop の選抜圧を外す）も (ii) σ を締めるも、単独で
  両次元の判定水準に効く**（N09 の PR@1e-3 は base 0.110 → 0.132 / 0.130 / 両方 0.148、
  N07 は 0.224 → 0.276 / 0.343 / 0.443、いずれも 12/x/x 以上）。**束でしか効かないという棄却条件は不成立。**
  重要なのは**機序が別物**であること: σ 成分は hunt を 20-38% 増やし landed を減らし blocked を倍にする
  （＝ 深さ↔広さの線）が、**commit 成分は hunt 数も landed も動かさずに distinct だけを上げる**
  （N09: 62.7 → 62.8 hunts、61.7 landed、distinct 31.1 → 36.9）＝ **線の外側**。
  **その39 が `commit_tight` 全体に帰した署名は σ 成分だけのものだった。**
  3D の判定水準を担いでいるのは commit 側（`commit_tight` 対 `commit_place` は 1e-3 で p=0.053、
  1e-5 で p=0.38 ＝ σ の上乗せは 1e-1 にしか有意に効かない）。**`best_f` は全腕・全 seed で base と一致。**
- **その分解は「commit は無条件に足せる」を意味しない**（その41）。**深さ律速の 2 関数**
  （N06-Shubert2D / N08-Shubert3D、**各 30 seed**）では **`commit_place` は全水準・全カラムで完全な帰無**
  （N08 の PR@1e-3 15/2/13・p=0.93、N06 は 14/2/14・p=0.92）で、**符号反転は `sigma_only` が単独で全部担う**
  （N08 の PR@1e-1 0.347 → 0.194、**30/30 seed 敗け**）。**ただし「無害」は単独腕に限る**:
  `commit_tight` 対 `sigma_only` を直接対にすると **commit の上乗せは負**
  （N06 の PR@1e-5 0.422 → 0.306、5/1/24、p=0.0005。N08 の PR@1e-3 0.105 → 0.080、3/1/11、p=0.026）
  ＝ **Vincent で見た加法性は深さ律速では成り立たない。**
  機序は **commit が配置しか縛らないこと**: run sigma が base（0.2×span）だと集団が anchor から拡散して
  **縛りが binding にならない**（単独帰無）、σ を締めて初めて binding になり、
  **Shubert では実際に効いている best-of-n_pop の「盆地は大域最適か」フィルタを失う代金**が出る。
  **この帰無は未発火ではなく相殺**（30/30 seed で診断カラムが変わり、`reported` 一致は 2 seed だけ）。
  **＝ commit も結局「関数依存」側の道具で、無条件の梃子は今のところ 1 つも無い。**
- **その組み合わせ損は用量反応で確認され、commit の路線は深さ律速側で閉じた**（その42）。
  commit の上乗せ Δ(r) = `commit_r{r}` − `sigma_only_r{r}` は **N08-Shubert3D で両判定水準とも
  比に対して単調にゼロへ向かう**（PR@1e-3: −0.028（3/1/16、p=0.0039）→ −0.020 → −0.002 → +0.001（σ=base））。
  配置比を揃えて σ だけを外した対（`commit_r{r}` − `commit_place_r{r}`）も単調
  （PR@1e-1: −0.185（0/0/20）→ −0.096 → −0.024）。**＝ 代金は σ の締め具合に比例し、緩めれば消える。**
  **ただしどの比でも深さ律速で得にはならない**（N08 の最良 commit 腕は PR@1e-1 0.311 対 base 0.344）
  ＝ **commit は被覆律速専用**。**N06-Shubert2D では単調にならないが、そこでは σ 自体が
  用量反応をしていない**（`sigma_only` の利得は r=0.10 の 1 点に集中、0.25 / 0.50 は base と平ら）
  ＝ **機序の否定ではなく、その領域にダイヤルが無い**。
- **σ 成分の「2D 限定」は 30 seed でも再現する**（その41）。N06-Shubert2D の PR@1e-5 は
  0.196 → **0.422**（28/2/0、A12=0.97）で**粗い水準の代償は有意でない**（1e-1 は 11/4/15）
  ＝ 2D-Shubert では無償。**同じ σ が N08-Shubert3D では PR@1e-1 を 0/0/30 で落とす。**
  **N08 の 1e-5 が判定に使えないことも 30 seed で再確認**（base の visited@1e-5 は 30 seed すべて 1.000）。
- **3D の niching 測定はもう「高く」ない**（その40）。**N08-Shubert3D も `--fast-scoring` で 1 run 7 秒**
  （その34・その35 の「8.4 分 / 3 並列 11 分」は素の採点時の値）。**seed を削る前にコスト表を見ること。**
- **N08-Shubert3D の 1e-5 は判定に使えない** — base が 5 seed すべてちょうど 1 解（PR = 0.01）。
  **3D の判定は 1e-1 / 1e-3 で行う。**
  **これは N08 固有の事情で 3D 一般の規則ではない**（その39）: N09-Vincent3D の base は
  1e-5 でも 22.4 解あるので、**N09 では 1e-5 も判定に使える**。
- **N09 は「高い関数」ではない**（その39）。1 run 401 秒に見えていたのは採点側で、
  **最適化そのものは 6.2 秒**。`diagnose_niching.py --fast-scoring` で **2 腕 × 15 seed が 118 秒**。
  **その22 の「並列 2 本まで（3 本は OOM）」も素の採点時の制約**なので、seed を削る前に
  [コスト表](acceptance_topology.md#1-run-の実測コスト40-分枠の計画はここから引くその32その37-の実測)を見ること。
- **規則側の梃子は全部閉じた**（その29）。**σ のスケールと受理規則という構造的に無関係な 2 つの介入が、
  同じ深さ↔広さの線の上を動く**（どちらも distinct を増やし `blocked` を 4-5 倍にし landed を減らす、
  同一の署名）。位相分け（枯渇まで親比較、枯渇後だけ最近傍置換）も**深さを分離しない** —
  最初の枯渇までに稼げるのは最初の 1 盆地の深さだけで、**必要な深さは境界の守られない側に全部ある**。
  **1 本の hunt に落ちる評価回数を変えない限り線から出られない**ので、残るのは配分側。
- **ただし「規則側は全部閉じた」は不完全だった**（その30）。**Shubert の深さを止めていたのは
  `hunt_level_tol`** で、`has_exhausted` 以降の hunt は `basin_best <= hunt_level_tol * f_init_scale`
  で解放される（`mceso.py:919-928`）。既定 1e-6 では**解放水準が eps=1e-3 と eps=1e-5 の間**に落ちるので、
  捨てた盆地の 9 割が (1e-5, 1e-3] に溜まる。1e-8 にすると **N06 の PR@1e-5 が 0.17 → 0.76**
  （15 seed 全勝、A12 = 1.00、粗い水準の代償は有意でない）＝ **本テーマ最大の利得**。
  **N07-Vincent2D では no-op**（被覆律速なので深さの梃子は効かない、その21 の二分法どおり）。
  **その29 の「1 本の hunt に落ちる評価回数を変えない限り線から出られない」は正しく、
  `hunt_level_tol` がまさにその評価回数を決める規則だった。**
  **採用可否は未決。ただし固定値の掃引はもうしないこと**（その35）: 解放水準は
  `tol × f_init_scale` で、`f_init_scale` は 2D 145 / 3D 2493 と**次元で 17 倍動く**ので、
  **「2D の最良は 1e-7、3D の最良は 1e-8」は矛盾ではなく絶対つまみを次元不変と誤読した結果**。
  議論は eps 相対の形で行う。
- **`blocked` が大きいことは「回収可能な在庫がある」ことを意味しない**（その30）。
  報告集合を成分に分けると `blocked` は**全部「最後の hunt の生きている population」**で、
  置き去りの盆地ではなく**予算が尽きた時点の現在地**だった。入って捨てて戻らなかった真の在庫は
  **N06 で 0.3、N07 で 0.0**（K = 18 / 36）。**成分に分けるまで在庫の有無は判定できない。**
- **BBOB-24 dim2 / 5000 評価の gate は「枯渇後だけを触る介入」に対して構造的に盲目**（その29）。
  `phased` は**全生成のおよそ半分で発火している**のに全 24 関数で tie_count = 20。理由も測った:
  **24 run のうち最初の枯渇より後に best_f が改善した run は 0 個**。
  **この gate を通ったことは安全の証拠にならない**（その26 の「発火していない」より強い）。
- **その盲目は全 24 関数で直接確認され、`hunt_level_tol` の安全性の側は閉じた**（その34）。
  BBOB-24 dim2 × 5 seed = **120 run で `post_gain > 0` がゼロ**。一方で水準節の解放は
  **97,538 回**発火し、その 53,507 回（1e-7）は tol を締めれば逆に倒れる
  ＝ **規則は猛烈に働くが、働く位置が常に best_f 確定後**。
  **SR@1e-10 が下がりえないことは外挿ではなく全 24 関数の直接測定になった。**
  **効果側も 3D で α を越えた**（N08-Shubert3D、8 seed、PR@1e-3 0.12 → 0.32、p = 0.0078、A12 = 1.00、
  粗い水準は 0.34 → 0.34 で不動）。**`best_f` は 8 seed とも両腕一致** ＝
  変種は最深の 1 点を動かさず、深く報告できる解の数だけを増やす。
- **eps 相対版（c=0.1）の安全性は推論ではなく直接測定になった**（その37）。BBOB-24 dim2 × 20 seed × 予算 2 点
  = **960 run すべてで `best_f` がバイト一致**し、SR@1e-10 は両腕 0.9208（5000 評価）/ 0.9625（20000 評価）、
  関数別も 24/24 で tie 20/20。水準節は 30 万回発火し軌跡も 8/35 run で分岐するが、
  **分岐は全部 `best_f` 確定後**（その33 の (c) 型）。**端点が 1 つある**: `f_init_scale` が下限 1e-300 に
  張り付く run では `L / f_init_scale` が 1e294 になり水準節が全 hunt を無条件解放するので、
  **採用形は `min(rel_level / f_init_scale, 既定)` にクランプすること。**
  **ただしこのクランプの形はその43 で否定された**（下記）。
- **eps 相対版は「締める規則」ではなく、`f_init_scale = 1` を境に符号が反転する規則**（その43）。
  base の実効水準は `1e-6 × f_init_scale` なので、**Shubert 側（142 / 2511）では締め、
  Vincent 側（N05 0.32 / N07 0.17 / N09 0.24）では緩める**。hunt 本数も逆向きに動く。
  **監査は 7 関数すべてで通った**（判定水準の悪化ゼロ、`best_f` は 150 対すべて一致、
  その36 の N06 の PR@1e-3 −0.082 は他のどこでも再現しない）が、**唯一の有意な利得（N07 の
  PR@1e-3 +0.025、p=0.021）は緩める側にあり、しかも hunt 本数を予算で揃えると α を越えない**
  （base22k 対 rel で p=0.079）＝ **深さの梃子ではなく「同じ予算で hunt を増やした」効果**。
  **帰結: その37 の `min(…, 既定 1e-6)` クランプは `f_init_scale < 1` の関数で常に効くので
  変種を base に戻し、その 3 関数を丸ごと無効化する。採用形は端点だけを止める形に書き直すこと。**
- **採用形は `max(f_init_scale, 1e-12)` に確定し、同時にクランプの必要性そのものが下がった**（その44）。
  3 形を並べて測ると、商を書き換えるセル数は BBOB-24 dim2 の 960 セル中 **既定値 88 / 上限 1e-2 が 4 /
  下限 1e-12 が 2**。**既定値クランプは niching の 3 関数だけでなく BBOB の 9 関数 88 セルに効いている。**
  下限形と上限形は**どちらも `best_f` が 960 セルで base と一致**し、niching 側でも無クランプ版と
  **315 セル完全一致**（＝ 介入を 1 行も削らない）。一方 **既定値形は N05 / N07 / N09 の 270 セルで
  base と完全一致** ＝ その43 の予言どおり利得を消す。
  **そして止めるはずだった端点は base と挙動が同じだった**: F07-StepEllipsoidal seed 19 は
  `f_init_scale` が床 1e-300 に張り付いて tol が 1e294 になるが、**水準節の発火回数は 3 腕とも一致**
  （539 / 2678）。理由は床に張り付く条件が「初期集団が `f = 0` を踏んだ」ことで、
  **`basin_best = 0` はどの正の tol でも節を真にする**から。`best_f = 0` / `post_gain = 0` なので代金も無い。
  **＝ クランプは事故対策であって採用条件ではない**（その37 の条件 (a) は性能条件ではなかった）。
  上限形を採らないのは、1e-2 が F22-Gallagher21 の商 0.01016 のすぐ外側にあり
  **端点でないセルを掴む**ため（下限側は物理的な床まで 288 桁の余裕がある）。
- **c の内点は無い。ただし採用候補の c = 0.1 は角の内側で、角は `L = eps_target`（c = 1.0）にある**（その46）。
  N06-Shubert2D の 6 腕掃引（30 seed）で **PR@1e-3 が base に戻るのは c = 10 だけ**で、
  **そこでは PR@1e-5 の利得も消える**（0.183 対 base 0.196）＝ 深さ↔広さの線はここでも成り立つ。
  一方 **c = 0.1 → 1.0 では代償と利得が同時に良くなる**（PR@1e-3 の落ち幅 −0.063 → −0.039、
  PR@1e-5 0.743 → 0.772）。機序は 2 つ: **深さの利得は `L ≤ eps_target` の階段関数**
  （c=3 で PR@1e-5 が 0.41 に崩れる）、**粗い水準の代償は hunt 本数そのもの**（25.5 → 29.1、base 29.3）。
  **3D も同じ向きで、c = 0.1 が 30 seed で払う PR@1e-1 の代償（p=0.0296、その34 の 8 seed では見えなかった）が
  c = 1.0 では消える**（p=0.38）。
- **その c = 1.0 の BBOB 安全性は c = 0.1 と同じ強さで通った**（その47）。BBOB-24 dim2 × 20 seed ×
  予算 2 点 = **960 セルで `best_f` が base と一致**し、`post_gain > 0` は**枯渇した 902 run すべてでゼロ**、
  SR@1e-10 は両腕 0.9208 / 0.9625。**同点は未発火ではない**（水準節の発火回数が base と違うセルは
  244/480・364/480、総発火は c=0.1 の 49,824 に対し **c=1.0 が 55,691 ＝ 12% 多い**）。
  さらに **`best_f` だけでなく 1e-10 への到達評価回数も 480/480 で一致**し、
  **履歴が分岐した 277 run の 277 全部で「分岐より前に最終 `best_f` が確定」**していた
  （その33 の (c) 型を推論ではなく計数で確認）。
  **＝ 採用候補の係数は c = 0.1 → c = 1.0 に差し替えてよい。ただし c = 1.0 の niching 側の監査は
  N06 / N08 の 2 関数だけ**（その43 の 5 関数監査は c = 0.1 のもの）。
- **残段（N08 の 1e-4 → 1e-5）を決めているのは σ 床節で、停滞節は一度も binding にならない**（その54）。
  段を作る報告解 129 点は **129/129 が解放された hunt 由来**で、解放時は `level_ok = False` /
  `sigma_floor_ok = True`、**binding は必ず σ 側**（seed 方向一致 15/15）。
  **rho-greedy の塞ぎ（`block`）も予算切れ（`budget`）も 0/129 ＝ 残段は報告・採点側の現象ではない。**
  停滞節は解放の **495 評価前**に成立済み（必要量 225 に対し `no_improve` 720）なので
  **`hunt_no_improve_mult` はこの関数では解放時刻を動かせない**（その25 の機序がこれ）。
  σ は床の **1.449 倍**で止まり、その段の hunt の 94% が 1e-5 に届いていない。
  **ただし「σ を緩めれば深くなる」はこの測定では言えない**（深い段が深いのは水準節で解放されたから ＝ 同語反復）。
- **その「言えない」に腕で答えが出た: 残段は σ の解像度で決まっており、余地を与えると閉じる**（その55）。
  N08-Shubert3D 40 万評価 × 15 seed の対で、**`exhausted_sigma_tol` 1.5 → 1.0 が PR@1e-5 を 0.754 → 0.837**
  （15/0/0、A12=1.00、代金は粗い水準に −0.016・p=0.0494）、**`sigma_floor_ratio` 1e-6 → 1e-8 が 0.863**
  （15/0/0、**段は 15/15 seed から完全に消え、粗い水準も distinct も代金ゼロ**、p=0.93）。
  **＝ 締める側（床節）より解像度側（床そのもの）のつまみの方が無償。**
  機序は hunt 数ではない（本数は 538 → 530 / 490 と**減る**のに landed@1e-5 は 114 → 194 / 269、
  blocked@1e-5 は 8.6 → 0.6 / 0.0）＝ **1 本あたりの到達精度が上がっている。**
  `best_f` は `_sig10` が 15/15 seed 一致、`_fl08` は**むしろ深い**（9/6/0、p=0.0046）。
  **N08 は深さ律速でなくなり被覆律速になった**（1e-5 でも `reported = distinct = 69.9`、`blocked = 0`、
  報告点数は採点上限 162 未満 ＝ 残る 11 解は浅いのではなく報告集合に niche が無い）。
  **どちらも本体の既定なので、BBOB gate を通すまで採用候補にしない**（問い 1）。

## 1 サイクルの手順

**このループは 1 時間ごとに走る。前の回がまだ走っている可能性があるので、手順 0 と 1 を飛ばすと二重着手になる。**

0. **ブランチを合わせる** — `git fetch origin && git checkout research-loop && git pull --rebase origin research-loop`（無ければ main から作る）。**成果は全部この 1 本に積む。** 実行ごとにブランチを切らない。切ると前回の続きから進めなくなり、統合されない成果物が散る。main には触らない（人がマージする）。
1. **問いを 1 つ claim する** — 「未解決の問い」の上から、まだ claim されていないものを 1 つ選び、その行に `(claimed YYYY-MM-DD HH:MM UTC)` と書いて**即コミット・push する**。これで他の回は別の問いを選ぶ。**2 時間以上前の claim は放棄されたものとみなして奪ってよい**（奪ったら時刻を書き換える）。
2. **統合の回かを判定する** — 「作業ログ」の件数が **8 件を超えていたら、新しい実験をせずに統合作業をする**。すなわち: ログの結論を `acceptance_topology.md` の該当節に集約し、決着した問いを「未解決の問い」から消し、ログを直近 3 件＋要約に畳む。積み上がらない一番の原因は記録が増えるだけで整理されないことなので、これは実験より優先する。
3. **先行研究を潰す** — 実装の前に、隣接分野の語彙で検索する（下記「先行調査の鉄則」）。既にあるなら問いを畳んで記録し、次の問いへ。
4. **設計する** — 何を測れば白黒つくか、どういう結果なら仮説が否定されるかを先に書く。撤退条件のない実験はしない。
5. **実装して回す** — 小さく回して配線を確認してから本測定。既存スクリプトで足りるなら新規作成しない。**1 回の計算は 40 分以内**に収める。収まらないなら関数か seed を削り、削ったと書く。
6. **分析する** — 対応のある検定と効果量、seed 方向一致率。平均だけで結論を出さない。
7. **記録してコミットする** — 「作業ログ」に追記し、claim を外して結果を書く（決着したら問いを消す、続きがあれば次の問いとして書く）。**否定的結果も機序つきで残す**。`research-loop` に push する。push が競合したら `git pull --rebase` して再試行。

**1 回で全部やろうとしない。** claim した問いが 40 分で終わらないと分かったら、そこまでの結果と「次はここから」をログに書いて終える。中途半端な状態を残すより、次の回が続きから入れる形にすることが優先。

## 守る規則（これまでの失敗から）

**先行調査の鉄則** — 新しい定式化を思いついたら、**実装より先に 4 分野以上の語彙で検索する**。この研究では 2 回、提案の中核が先行研究と一致して撤退した。

- 進化計算（niching / QD / EDO）だけでなく、ロバスト最適化（K-adaptability, ROMS）、設計工学（solution space engineering, set-based design）、計算化学（disconnectivity graph, barrier tree, NEB）、統計（cluster tree）、TDA（merge tree, persistence）、能動学習（level set estimation）の用語で引く。
- 「barrier tree は調べたが disconnectivity graph では引かなかった」で 1 日を失った。**同じ概念の別名を列挙してから検索する。**

**測定の鉄則**

- **単一 seed で結論を出さない。** 1 seed では NM-Restart が最良と出た関数で、3 seed では最下位になった。
- **集計から落ちた対象を必ず報告する。** 比が定義できない関数を黙って除くと順位が変わる（実際に変わった）。
- **定義を変えたら結果がどう動くかを測る。** τ・重複除去半径・行動記述子・シナリオモデルはいずれも答えを桁で動かした。定義依存性は欠陥ではなく報告事項。
- **推定器の誤りの向きを述べる。** 線分による連結判定は繋がりを見落とす側にしか誤らない、など。
- **後処理の利得は 1 手法で測らない。** 報告規則のように**手法非依存に当てられる**ものは、
  1 手法で測ると必ず「効く」ように見える。その20 は MC-ESO 単独で PR@1e-1 を 0.25 → 1.00 に
  上げたが、その28 で 7 手法に与えたら**全員が上がり順位は 1e-3 以下で不動**だった。
  **他手法にも与えられる介入は、他手法にも与えてから読む。**
- **同一 run を 2 通りに採点できるなら、そうする。** その28 は 1 セットの run を
  2 つの報告規則で採点したので、ペアリングが厳密で追加評価はゼロだった。
  比較のために run を 2 回回すと、seed 差が交絡として入る。

**リポジトリに何を残すか**

差分の 99.7% が機械の吐いた生 CSV になり、レビューできない状態になった（2026-09-03 に整理）。

- **行単位の生 CSV は `.csv.gz` で置く。** 生のまま置いてよいのは数百行までの集計結果。
- **数値は必ず docs に書き出す。** CSV は再解析のための控えであって、結論の置き場ではない。
  docs を読めば結論が分かる状態にしてから commit する。
- **路線が畳まれたら、その生データも消す。** 結論は `acceptance_topology.md` に残っており、
  git の履歴からも取り出せる。畳んだ路線の生データを抱えたままにしない。
- 1 回のサイクルで `analysis/` に足す行数は、gzip 前で 10 万行を目安に収める。
  超えるなら集計してから置く。

**main へのマージ**

`research-loop` は 1 日 1 回を目安に `main` へマージする（マージはユーザーが決める）。
溜めると差分が読めなくなり、読めない差分はレビューされない。

**MC-ESO を壊さない**

- 診断用の変種は本体を書き換えず別ファイルに置く（例: `mceso_crowding.py`）。
