## 1 サイクルの手順

**このループは 1 時間ごとに走る。前の回がまだ走っている可能性があるので、手順 0 と 1 を飛ばすと二重着手になる。**

0. **ブランチを合わせる** — `git fetch origin && git checkout research-loop && git pull --rebase origin research-loop`（無ければ main から作る）。**成果は全部この 1 本に積む。** 実行ごとにブランチを切らない。切ると前回の続きから進めなくなり、統合されない成果物が散る。main には触らない（人がマージする）。
1. **問いを 1 つ claim する** — 「未解決の問い」の上から、まだ claim されていないものを 1 つ選び、その行に `(claimed YYYY-MM-DD HH:MM UTC)` と書いて**即コミット・push する**。これで他の回は別の問いを選ぶ。**2 時間以上前の claim は放棄されたものとみなして奪ってよい**（奪ったら時刻を書き換える）。
2. **統合の回かを判定する** — 「作業ログ」の件数が **8 件を超えていたら、新しい実験をせずに統合作業をする**。すなわち: ログの結論を `acceptance_topology.md` の該当節に集約し、決着した問いを「未解決の問い」から消し、ログを直近 3 件＋要約に畳む。積み上がらない一番の原因は記録が増えるだけで整理されないことなので、これは実験より優先する。
3. **先行研究を潰す** — 実装の前に、隣接分野の語彙で検索する（下記「先行調査の鉄則」）。既にあるなら問いを畳んで記録し、次の問いへ。
4. **設計する** — 何を測れば白黒つくか、どういう結果なら仮説が否定されるかを先に書く。撤退条件のない実験はしない。
5. **実装して回す** — 小さく回して配線を確認してから本測定。既存スクリプトで足りるなら新規作成しない。**1 回の計算は 40 分以内**に収める。収まらないなら関数か seed を削り、削ったと書く。
6. **分析する** — 対応のある検定と効果量、seed 方向一致率。平均だけで結論を出さない。
7. **記録してコミットする** — 「作業ログ」に追記し、claim を外して結果を書く（決着したら問いを消す、続きがあれば次の問いとして書く）。**否定的結果も機序つきで残す**。`research-loop` に push する。push が競合したら `git pull --rebase` して再試行。

**1 回で全部やろうとしない。** claim した問いが 40 分で終わらないと分かったら、そこまでの結果と「次はここから」をログに書いて終える。中途半端な状態を残すより、次の回が続きから入れる形にすることが優先。

## 守る規則（これまでの失敗から）

**先行調査の鉄則** — 新しい定式化を思いついたら、**実装より先に 4 分野以上の語彙で検索する**。この研究では 2 回、提案の中核が先行研究と一致して撤退した。

- 進化計算（niching / QD / EDO）だけでなく、ロバスト最適化（K-adaptability, ROMS）、設計工学（solution space engineering, set-based design）、計算化学（disconnectivity graph, barrier tree, NEB）、統計（cluster tree）、TDA（merge tree, persistence）、能動学習（level set estimation）の用語で引く。
- 「barrier tree は調べたが disconnectivity graph では引かなかった」で 1 日を失った。**同じ概念の別名を列挙してから検索する。**

**測定の鉄則**

- **単一 seed で結論を出さない。** 1 seed では NM-Restart が最良と出た関数で、3 seed では最下位になった。
- **集計から落ちた対象を必ず報告する。** 比が定義できない関数を黙って除くと順位が変わる（実際に変わった）。
- **定義を変えたら結果がどう動くかを測る。** τ・重複除去半径・行動記述子・シナリオモデルはいずれも答えを桁で動かした。定義依存性は欠陥ではなく報告事項。
- **推定器の誤りの向きを述べる。** 線分による連結判定は繋がりを見落とす側にしか誤らない、など。

**MC-ESO を壊さない**

- `SR@1e-10` を下げる構成は採用しない（多解の改善でも例外なし）。
- 既定値を変えたら **BBOB-24 dim2 / n=20 で SR@1e-10 93.5% / evals_succ_mean 798** と一致することを確認してからコミットする。
- 診断用の変種は本体を書き換えず別ファイルに置く（例: `mceso_crowding.py`）。

   始めれば 40 分に収まる。確認すべきは、τ=0.1 が dim3 で安全・dim5 で崩れること、
   その崩れが 150 本のプールで消えること、全滅の機序が次元不変であること（ρ ≈ −0.9）。
2. **帯の中の候補数で τ を決める適応版にする** — 上が再現できてから。許容帯に候補が K 個
   未満なら規則は空振りする。プール本数ではなく帯の中の候補数を条件にした形（候補が K 個に
   満たない間は τ を広げる）にすれば、次元ごとに本数を手で決めずに済む。dim2 / 5 で固定 τ 版と
   比較する。棄却条件は、適応版が固定版に勝てないこと。
   聞かれる。全滅率と spread の関係（ρ≈−0.85）も、τ=0.1 の安全性も、次元が上がれば変わりうる
   （高次元では任意の半空間に集合全体が入る確率が下がるので、全滅そのものが起きにくくなるはず）。
   dim 3 / 5 で `scripts/scenario_value.py --tau` を回して τ の安全域が残るかを測る。
   棄却条件は、dim 5 で τ=0.1 がどれかのモデルで負け越すこと。
3. **同じ探索の出力から選ぶ形で比較する** — 予算の交絡は否定できた（下記その10）が、参照規則がオフラインの multistart プールから選び、手法が自前の探索から選ぶという非対称は残る。共通の探索履歴（例: IPOP-CMA-ES の全評価点）から各規則が選ぶ形に揃えて測り直す。ただし本プロジェクトは「run が報告したものを採点する」方針を採っているので（`final_solutions` のみ採点）、履歴を使う比較はその方針と衝突する。衝突をどう扱うかを先に決めること。
   プールから選ぶ参照規則で、手法は自前の探索から選ぶ。評価回数は揃えているが、
   「同じ探索の出力から選ぶ」形での比較になっていない。共通の探索（例: IPOP-CMA-ES の全履歴）
   から各規則が選ぶ形に揃えて測り直す。
4. **distinct が効くのが instance だけなのはなぜか** — 受容集合の連結成分数
   （`analysis/components_bbob.csv`）で層別して確かめる。棄却条件は、成分数で層別しても
   両モデルの ρ 差が縮まらないこと。
5. **深さと頑健性の両立** — 掘り切るまで親比較、掘り切った後だけ最近傍置換の 2 段構え。
   SR@1e-10 を守れるかが判定基準。
6. **QD の残る欠点の検証** — BD 次元の呪い、ノイズ下のエリート楽観バイアス、
   QD-score のアーカイブ解像度依存。1 回に 1 つ。
7. **CMA-ME での再測定** — pyribs が入るなら QD の評価をやり直す。
8. **ゲーム応用での検証** — GEEvo（経済バランス、実装公開）か PCG Benchmark。
9. **投稿先の選定** — GECCO の BBSR トラック。締切と要求形式を調べる。

### 2026-09-02 その7（許容幅は未知の種類を知らなくても選べる — 決着）

前の回で「τ を選ぶにはどのモデルに直面するか知っている必要がある」を弱点として残した。
ただしどのモデルかは**未知の側の性質**であって地形から観測できる量ではないので、地形特徴で
τ を選ぶ筋は原理的に成り立たない。使える問いは「全モデルで害にならない τ があるか」だけ。

τ を 8 水準（0.02〜2.0）に振り、3 モデルで BBOB-24 × 5 seed を測った
（`analysis/tau_{constraint,instance,tilt}.csv`）。対応のある Wilcoxon（α=0.05）で
関数ごとの勝ち負けを数え、`scripts/tau_choice.py` にまとめた。

| τ | constraint | instance | tilt | 最悪 |
|---|---|---|---|---|
| 0.02 | 3-0 | 2-0 | 4-1 | +2 |
| 0.05 | 5-0 | 4-1 | 6-1 | +3 |
| **0.1** | **7-0** | **6-1** | **6-2** | **+4** |
| 0.15 | 6-1 | 6-1 | 5-3 | +2 |
| 0.25 | 7-1 | 6-1 | 3-4 | −1 |
| 0.5 | 9-0 | 9-1 | 2-10 | −8 |
| 1.0 | 9-1 | 9-2 | 1-11 | −10 |
| 2.0 | 9-1 | 8-1 | 1-11 | −10 |

**弱点は消えた。** τ = 0.1 は 3 モデルすべてで勝ち越し、最悪でも 6 勝 2 敗。未知の種類を
知らずに固定値で使える。モデル依存が問題になるのは τ ≥ 0.25 の広い許容幅だけで、
そこから先は tilt での損失が急に効いてくる（0.25 で −1、0.5 で −8）。

制約と留保:

- 最適点の**位置**は 5 seed では確定しない。0.05 / 0.1 / 0.15 の最悪値は 3 / 4 / 2 で
  差が小さい。頑健なのは「内部に安全域が存在すること」と「0.25 を超えると崩れること」の 2 点。
- 効果の大きさは τ = 0.1 では小さい。禁止領域下の全滅率は 35% → 33% しか下がらない。
  大きく下げる（24%）には τ = 1 が要るが、それは tilt で 1 勝 11 敗になる設定。
  **安全な設定と効果の大きい設定は別**というのがこの表の一番の含意。
- 深さは構成上不変（最良点を必ず残す）。追加評価もゼロ。

次: ここまでの τ 評価はオフラインプールから選ぶ参照規則としてのもの。実手法の出力に
**後処理**として掛けて同じ効果が出るかを確かめる（未解決の問い 1 に格上げ）。

### これまでの到達点（その1〜その6 を集約、詳細は acceptance_topology.md）

- 多解手法の報告集合は、未定式化基準のもとで「上位 K を報告する」に勝ち越さない。
- ただし結論はシナリオモデルで反転する。モデルごとに**別の性質が採点されている**ため:
  instance では distinct な解の数（ρ=0.83）、constraint では空間的な広がり（0.33）、
  tilt では何も効かない。「たくさん返す」ことはどのモデルでも効かない。
- 受容集合が単一の塊の関数では、どんな選択規則も上位 K 取りに勝てない（11 関数すべて A12=0.50）。
- 脆さの原因は受理規則。親比較を最近傍置換にすると劣化 −13 → −2、ただし深さが 100% → 0%。
- 勝率と期待 regret は別の判定で、禁止領域では 53% のセルで食い違う（tilt 15% / instance 17%）。
  MC-ESO は 24/24 で順位勝ちしながら平均勝ちは 10/24。両方で勝つのは NM-Restart だけ。
- その原因は全滅。禁止領域は報告集合を丸ごと消しうるので損失に上限がない。損失は全滅時にしか
  出ず（生存時の超過 regret は中央値 0.00）、全滅率は spread が決める（ρ≈−0.85、24/24、
  禁止領域を 4 倍にしても不変）。
- 15 seed でも結論は不変（中央 A12 は 5 seed 版の ±0.05 以内）。seed 内で A12 を取り直しても
  符号反転は 288 セルで 0 件なので、プーリングは原因ではない。
- 測定上の教訓: 関数をまたいで相関をプールしてはいけない（スケールが桁で違い、符号が反転する）。
