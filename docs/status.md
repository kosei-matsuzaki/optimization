## 確定した事実

- **差はほぼ Vincent だけで作られている。** Vincent 2 関数を除くと NMMSO との平均差は
  0.06、入れると 0.21。
- **PR は evals/K でも K でも決まらない。** 同じ evals/K の 10 倍幅の中で PR は 0.00〜1.00。
  決めているのは**予算応答**（予算を新しい最適解に変換し続けられるか）。r3pso は完全飽和
  （10 倍で 0.48 → 0.47）、MC-ESO は高 K でだけ飽和、NMMSO のみ変換し続ける。
- **報告枠は制約ではない。** 採点上限 max(100, 2K) に対し MC-ESO は 88 点しか報告していないが、
  全履歴から選び直しても eps ≤ 1e-3 では順位が 1 つも動かない。
- **律速は 2 種類。** Vincent は被覆律速（一様描画＋固定反発半径 対 対数間隔の盆地）、
  Shubert は深さ律速（盆地は見つけるが掘り切らない）。
- **σ を局所盆地間隔に落とすと 2D で大きく効く。** N07 の PR@1e-3 が 0.22 → 0.44
  （15 seed 全勝、A12 = 1.00、p = 0.0006）。hunt 数の交絡は排除済み。
- **受理規則が深さと広さを 1 つのつまみで決めている。** 親比較なら深さ、最近傍置換なら広さ。
  MC-ESO で SR@1e-10 が 100% → 0%。DE / PSO でも同傾向。

## いちばん弱い環

1. **正規予算での比較が 1 度もない。** 全判定が 0.1 倍予算。査読で最初に突かれる。
2. **採択できた改善がゼロ。** 効いた梃子は次元で符号が反転して入れられていない。
   このままでは「潰した路線の一覧」しか残らない。
3. **ベースラインに疑いがある。** NM-Restart が Shubert でだけ報告点数 1、PR 0.00。
   実装不具合の可能性が高く、未確認のまま比較表に載っている。
4. **NMMSO がクラウド環境で動かない**（Python 3.11 で `pynmmso` が落ちる）。
   首位の手法を回せない環境で比較を続けている。

## 次に効く一手

**σ の梃子が 3D で符号反転する原因を潰す。** これが唯一「効くと分かっているもの」で、
そこが直れば採択候補になる。機序は診断済み（hunt を増やす代わりに 1 本 1 本を浅くする）
なので、深さ側に安全弁を付ける形（`hunt_level_tol` と枯渇後 gate）が次の手。

並行して優先度が高いのは**正規予算の比較を Actions に載せる**こと。弱い環の 1 番を消し、
0.1 倍予算での判定が正規予算でも成り立つかを一度確かめておく必要がある。
