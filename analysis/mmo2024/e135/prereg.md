# e135 事前登録 —— NMMSO の配線が D=10 で正しいことを公表値と照合する（キュー 2）

登録: 2026-09-17 06:45 UTC（run を出す前に書いた）。実行役サイクル その135。

## 何を守るための測定か

頭の主張は **「GECCO'2024/'2025 suite の D=10 で niching 手法 2 本が無協調の多スタートに 16 問全敗する」**
（p=3.052e-5、[status.md](../../../docs/status.md) の堅い 1）。その足元で唯一検証されていないのが
**この harness の NMMSO が高次元で正しく動いているか**である（新 suite D=10 で Score 0.1548 ＝ 素の多スタートの 4 分の 1）。
2D/3D の N04-N10 は PR@1e-5 ≥ 0.984（その50）で照合済みだが、**0.984 →（D=10）→ 0.1548 の落差そのものは未検証。**

## 測るもの

CEC2013 niching の **N18-CF3-10D / N19-CF4-10D / N20-CF4-20D** を **公式予算 400,000 評価**で NMMSO に回し、
`cec_pr_1e-5`（**rho 経路**、`core/runner.py:_niching_counts` の `count_goptima` 側）を
その134 が取った公表値（Fieldsend 2014 表 IV、50 run、公式予算）と比べる。

| 関数 | D | K | 公表 PR@1e-5 |
|---|---|---|---|
| N18-CF3-10D | 10 | 6 | **0.633** |
| N19-CF4-10D | 10 | 8 | **0.443** |
| N20-CF4-20D | 20 | 8 | **0.178** |

**採点器は新 suite の最近傍経路とは別**（`niche_rho=0.01` があるので rho 経路に入る）。**これは意図どおり** ——
照合したいのは採点器ではなく NMMSO の配線で、採点器の側は その127-131 で別に検証済み。

## seed 数と根拠（コスト実測 2026-09-17）

- frac 0.05（20,000 評価）の probe = 測定 3 秒。**frac 1.0（400,000 評価）の N18 1 run = 51.6 秒**（実測、1 seed）。
- **N18 / N19 を各 15 seed、N20 を 10 seed**（20D は 1 run が重いので減らす）＝ **40 run**。
  3 関数を 3 プロセス並列（コンテナ 4 コア、規則は 3 本まで）で壁時計 15-20 分の見積り。
- 公表値は **50 run 平均**。こちらは 15/15/10 run 平均なので、**比較は「平均 ± 標準誤差」で行い、
  SE が判定幅（±0.10）に対して大きすぎる場合はその旨を明記する。**
- NMMSO は **seed を固定しても run 間で完全再現しない**（set のイテレーション順が object id 依存。環境節）
  ＝ seed は独立標本として機能する。

## 判定（事前登録）

**主判定**: 3 関数それぞれで **|実測平均 − 公表値| ≤ 0.10** なら**配線は妥当**と書き、[status.md](../../../docs/status.md) の弱い環 2 を閉じる。

**反証条件 (a)**: **±0.10 を外れ、かつこちらが低い側**の関数が 1 つでもあれば、**harness のバグを疑う側に倒す。**
その場合は**腕を作らず**、原因を特定するまで**新 suite の NMMSO の数値をすべて「検証中」と注記する。**
＝ **頭の主張（16/16）の前提が崩れる。**

**反証条件 (b)**: **こちらが高い側に ±0.10 を外れた**場合は公表値の条件違い（seed 数・予算・報告規則）を疑い、
条件を揃え直してから再判定する（**この回では結論を出さない**）。

**この測定が反証しうるもの**: 「NMMSO の配線は D=10 で正しい」。3 関数のうち 1 つでも低い側に外れれば、
**この研究のいちばん重い資産（16 問全敗）が harness のバグに帰属しうる**ことになる。
