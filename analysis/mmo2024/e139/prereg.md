## 判定（キュー 1 が先に書いたもの。ここで緩めない）

**主判定**: **問題ごとに NMMSO の Score が `Restart-Lander` を上回る問題が 1 つでもあれば、
「niching 手法は 16 問すべてで記憶なし多スタートに負ける」の 16/16 は崩れる。**
**崩れた場合、実行役は主張を書き換えない** —— **何問で崩れたかを数えてログに書き、俯瞰に上げる。**
（16 問平均 Score が 0.6238 / 0.6284 を上回るかも併記する。）

**反証条件 (a)（この修正が再測定の条件を変えている）**: **NMMSO の 16 問平均 Score が
旧既定の 0.1548 より下がったら**、修正以外の何かが動いている。**先に特定する** ——
**(i) 予算**: `n_reported` と**要求回数**（`len(history_f) >= max_evals` の側ではなく
呼ばれた回数。その136 の教訓「打ち切る側のカウンタで比を測るな」）、
**(ii) 報告**: 報告点数の分布、**(iii) seed**: seed 0 で揃っているか。
**特定できるまで「下がった」を結論にしない。**

**反証条件 (b)（CEC2013 で効いた 1 行は新 suite では効かない）**: **16 問平均 Score が
`0.1548 ± 0.02`（＝ [0.1348, 0.1748]）の内側に収まったら**、
**新 suite の低さは `swarm_size` では説明できない。そう書いてこの路線を閉じる**
（CEC2013 側の関門 4/5 合格は残る。撤回しない）。

## この設計で気をつける点（先に書いておく）

- **NMMSO は seed を固定しても run 間で完全再現しない**（set のイテレーション順が object id 依存。
  `acceptance_topology.md` の環境節）。**＝ 1 seed の差を「手法の差」と読める幅には限度がある。**
  帯 ±0.02 は旧既定との差（0.1548 対 今回）に当てるものであって、**再現性の帯ではない。**
  **16 問平均は 16 問の平均なので 1 問あたりの揺れは 1/4 に薄まる**が、
  **問題ごとの勝敗（主判定）は 1 run の値で決まるので、そこは 1 run の粗さを併記する。**
- **群 A は K=20、群 B は K=10** ＝ **1 run の PR は群 A で 0.05 刻み、群 B で 0.1 刻み。**
  **主判定は「上回る問題が 1 つでもあるか」なので、対照 0.6284 との差はこの刻みよりずっと大きく、粗さでは動かない。**
