# その115 事前登録 —— キュー 1「合法な報告規則で oracle 余地 0.2517 のどれだけが取れるか」

claim: 2026-09-12 06:29 UTC。**キュー 1 をそのまま実行**（方針欄 2026-09-11 の決定 (1) が名指しで許可）。

## 何を測るか

`Restart-Lander` の保存済み降下ダンプ（`e110/descents/*_seed0.csv.gz`、`e111/descents/*_seed100.csv.gz`）から、
**探索を 1 ビットも変えずに報告集合だけを作り直し**、5 水準の PR / F1 / Score を出す。16 問 × 2 seed。

採点は その112 と同一（`competition_setup_TR2024001.txt` §4）:
`PR(ε)=detected(ε)/K`、`precision(ε)=detected(ε)/n_reported`、`F1=2PR·prec/(PR+prec)`、`Score=(PR+F1)/2`。
集約は run → (seed 平均) 問題 → 16 問平均、水準 1e-1..1e-5 は等重み。

## 合法性の線（§5）

使ってよいのは **D・探索域・評価予算・ε_tight=1e-5・ε_loose=1e-1** だけ。
**K（NGM）も f\* も使えない。** したがって:

- **現行規則 `max(100, 2K)` は K を使うので、それ自体が規則違反である。** 対照としては残すが、
  「合法な規則」には数えない。
- `f ≤ f_best + ε` の f_best は **run が観測した最小値**であって f\* ではない（ダンプの `best_f` は
  f − f\* なので、閾値は `best_f ≤ min(best_f) + ε` と同値。**単調シフトなので実装可能な規則と一致する**）。
- **`land_opt` / `dist` はオラクル列**（真の最適の位置が要る）。**規則の定義には使わない。採点にだけ使う。**

## 腕（どれも K も f\* も使わない）

| 記号 | 規則 |
|---|---|
| `cur` | 現行 = f 昇順 `max(100,2K)` 点（**対照・規則違反**） |
| `cap100` | f 昇順 100 点（固定 cap は合法） |
| `eps_loose` | `best_f ≤ min + 1e-1` の点すべて（(a)） |
| `eps_tight` | `best_f ≤ min + 1e-5` の点すべて（(b)） |
| `eps_loose_cap100` / `eps_tight_cap100` | 上の 2 つに固定 cap 100 を足したもの |
| `dedup_r` | **(c)** f 昇順に貪欲に走査し、既に採った点から距離 r 以内なら捨てる。r は探索域の幅に対する比（合法） |
| `eps_loose+dedup_r` | (a) と (c) の合成 |
| `oracle` | 各最適につき f 最小の 1 点（**実装不可能な上限**、その112 の 0.6156） |

`dedup_r` は着地点の座標が要るが **`e110` のダンプは座標を落としている**ので、
**同じ seed 0 を座標つきで回し直す**（`core/optimizers/restart_lander.py` の `_dump` に `x*` 列を足しただけ。
探索は 1 ビットも変えていないので `best_f` 列は e110 と一致するはず ＝ **恒等検査として突き合わせる**）。
座標の要らない腕（`cur` / `cap100` / `eps_*`）は **2 seed 32 run**、`dedup_r` は **seed 0 の 16 run** で測る。

## 事前登録した棄却条件（キュー 1 の原文）

- **合法な規則のうち最良のものが 16 問平均 Score 0.45 に届かない**（＝ 余地 0.2517 の半分未満しか取れない）
  → **報告軸は「oracle でしか開かない」と書いて閉じ、3 手法には広げない。**
- **届く** → `Restart-Lander` は公式指標でも公表最良（TRDE-LR D=10 Score 0.6080）に手が届く位置にいるので、
  **3 手法に広げるかどうかを次の一手として書く**（MC-ESO / NMMSO は報告集合が保存されていないので再 run が要る）。

比較先 3 本: 現行 Score **0.3639**、oracle 上限 **0.6156**、公表最良 D=10 Score **0.6080**。

## 何が出たら仮説が否定されるか

- 仮説は「**F1 の分母（報告点数）は合法な規則だけで大きく減らせる**」。
- **否定される形**: どの合法な腕でも Score が現行 0.3639 から有意に上がらない、
  または上がっても PR の低下で相殺されて 0.45 に届かない。
  **この場合「報告軸は F1 の上でも実装可能な範囲では空」**と書いて閉じる。
- 検定は **16 問を対にした両側 Wilcoxon**（`method="exact"`）、効果量は rank-biserial。
  **規則ごとに `n_reported` を必ず併記する**（その112 §7 の cap 境界同値は ±1 最適の揺れを生む）。

## 結果は上限であって勝ちではない（俯瞰からの申し送りをそのまま置く）

oracle 上限 0.6156 が公表最良を上回るのは +0.0076 で **比較条件（2 seed・PIN01 対 15 instance・資料 1 本）の内側**。
報告規則を設計対象にすること自体は HVPI（PMC11505590）が占有、F1 は GECCO 競技が 2016 年から使っている。
**結果は「報告軸の決着」として書き、「勝ち筋」と呼ばない。**
