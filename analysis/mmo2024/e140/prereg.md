# その140 事前登録 — キュー 1 の残り: M01 / M02 / M04 / M10 の符号を 5 seed で確定させる

**書いた時刻: 2026-09-18 12:33 UTC（run の投入は 12:32 UTC。結果は 1 行も見ていない）。**

## 何を測るか

**その139 が「直した NMMSO（`swarm_size` 既定 `10·D`）が記憶なし多スタート `Restart-Lander` を上回る」と出した
4 問（M01 / M02 / M04 / M10、いずれも D=10・PIN01）について、seed を 5 本に増やして符号を確定させる。**

- **NMMSO**: `scripts/niching_baseline.py --methods NMMSO`、`--evals-frac 1.0`（正規予算 50 万）、
  **seed 2 / 3 / 4**（`--seed-offset` で与える。12 run）。既存の seed 0（その139）・seed 1（その139）と合わせて **5 seed**。
- **`Restart-Lander`**: 同じ 4 問・**同じ 3 本の追加 seed**（12 run）。既存は seed 0（`e115/descents/`）と
  seed 100（`e115/s1/descents/`、その139 が「seed 1」と呼んだ列）。
- 報告規則は **`eps_loose+dedup`（r = 0.05·span）** 固定。**統計量は `analysis/mmo2024/e115/analyze.py` の
  `rule_indices` / `score` / `paired` / `aggregate` をそのまま import する。新しい統計量は 1 つも定義しない。**

**seed の対応**: 2 手法の seed 値は揃わない（null の 2 本目は seed 100）。**これは 2 つの独立な手法の
独立な反復なので、対にするのは「問題」であって「seed 値」ではない。** seed をまたぐ集計は
**問題ごとに 5 seed 平均の Score を作り、その差を見る**形で行う。

## 判定（結果を見る前に固定する）

- **主判定**: **5 seed の対で、Score 差が正の seed が 4/5 以上の問題を「上回る」と数える。**
  **1 問でも残れば「16 問全敗」の撤回は確定**とし、**何問で崩れたかを俯瞰に上げる**（実行役は status.md を編集しない）。
- **反証条件 (a)**: **3 問（M01 / M04 / M10）とも 5 seed 平均の差が 0 をまたいだら**、その139 の 3 問は
  **2 seed の当たり**だった ＝ **「16/16 は崩れていない」で確定させ、この路線を閉じる。**
  （M02 は seed 1 で完全同値だったので、その139 の時点で既に 4/5 の候補から外れている。）
- **反証条件 (b)**: **`Restart-Lander` の seed 0 / seed 100 を保存ダンプから採点し直した値が、
  その139 の記録（M01 0.7600 / M02 0.6069 / M04 0.7189 / M10 0.6529、seed 0）と 4 桁で一致しなければ、
  seed 2 以降に進まず配線を先に直す。** ＝ **採点経路が当時と同一であることの関門。**

## 何が仮説を反証するか（1 行）

**「NMMSO は少なくとも数問で null に並ぶ／勝つ」という仮説は、5 seed 平均の差が 3 問とも 0 をまたいだ時点で反証される。**
逆に **4/5 以上の seed で正が残る問題が 1 つでもあれば、16/16 は撤回で確定する。**
