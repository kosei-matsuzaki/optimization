**(0-2) 計器そのものの点検。** その135 の probe は `len(history_f)` を「実呼び出し数」と呼んだが、
`core/optimizers/nmmso.py:59-60` は `len(history_f) >= max_evals` で記録を止めるので、
**`len(history_f)` は定義上 400000 を超えられない。**

## 3. 判定（キュー 2 に登録済みの文言をそのまま使う）

## 4. wrapper が無実だった場合に同じ回で足すもの（(c) の足場、CF4 の次元ばしご）

**その50 が照合したのは F4-F10（2D/3D）で、CF 族の次元依存は未測定。**
Fieldsend 2014 表 IV は **CF4 を 3 水準持っている**: **F15 = CF4-3D 0.668 / F17 = CF4-5D 0.538 / F19 = CF4-10D 0.443 / F20 = CF4-20D 0.178**。
**`N15-CF4-3D` と `N17-CF4-5D` を 3 seed ずつ**回して、**破綻が次元のどこで始まるかを測る。**
- **3D・5D が公表値の ±0.10 内なら、破綻は次元に依存する** ＝ (c) を「D が上がると乖離する」と限定して書ける。
- **3D から既に外れるなら、乖離は次元と無関係**で、**CF 族そのものの扱い**（合成関数の回転行列・シフト表）を次に見る。
**これは (c) の限定の強さを決めるための測定で、腕ではない。MC-ESO には触らない。**

## 4-ter. 追記（2026-09-17 12:44 UTC、**この腕の run を出す前に書いた**）—— 第 4 の腕 `sw10d`

**その134 が取得済みの本文を読み直したら、公表側のパラメータが逐語で書いてあった。**
Fieldsend 2014 の実験設定（`analysis/mmo2024/e134/refs/fieldsend2014_nmmso_cec.txt.gz` の 491-492 行）:

> *"We set the automatic merging tolerance tol = 10−6, the **maximum swarm size n = 10D**
> (where D is the number of design parameters) and the maximum number of swarms to increment max inc = 100."*

**`core/optimizers/nmmso.py:43` は `swarm_size: int = 10` を D に依らず直書きしている。**
＝ **D=10 では公表設定の 1/10、D=20 では 1/20。D=2 では 1/2。**
**その135 が「`swarm_size` は D=10 では容疑者ではない」と書いたのは、
`pynmmso` の*ライブラリ既定*（`4+floor(3·ln D)` ＝ D=10 で 10）と一致することを見たからで、
*論文の設定*と照合してはいなかった。** ライブラリ既定と論文の設定は別物である。
**これは「wrapper の細部」そのもので、しかも D 依存 —— 乖離が次元とともに開くこと（−0.23 / −0.41 / −0.18）と整合する。**

**腕 `sw10d`**: `swarm_size = 10 * D`（N19 では 100）。他は `base` と同一。**N19 を seed 100-104 の 5 本。**
**判定は他の腕と同じ基準をそのまま使う** —— **`base` から +0.10 以上動けば wrapper 側の欠陥。**
**反証条件**: **`sw10d` が `base` の ±0.05 内なら、`swarm_size` は原因ではない**と書き、(c) に倒す。
**注意**: これは `core/` の変更ではない（この腕はこのディレクトリの複製の中だけ）。
**`core/optimizers/nmmso.py` を直すのは、この腕が発火して原因が確定してからで、次サイクルの仕事とする。**
