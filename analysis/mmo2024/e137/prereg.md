## 2. 関門 (b) —— 測るもの

**`scripts/niching_baseline.py --methods NMMSO --evals-frac 1.0`（既存スクリプトをそのまま使う）** で
**N15-CF4-3D / N17-CF4-5D / N18-CF3-10D / N19-CF4-10D / N20-CF4-20D** を**公式予算 400,000 評価**で回す。
判定量は **`cec_pr_1e-5`**（`core/runner.py` の `count_goptima` 経路、報告集合は `max(100, 2K)` cap つき）—— その135・その136 と同一。
**新しい統計量は定義しない。**

**seed 数はキューの登録より増やして各 10 seed とする**（キューは各 5 seed。合計 25 → 50 run）。
**理由は その136 が自分で書き残した教訓** ——「判定の帯は 1 run が取りうる値の粗さから決めること」。
この 5 関数の 1 run は **K=8 なら 0.125 刻み、K=6（N18）なら 0.1667 刻み**しか取らないので、
**n=5 では SE が 0.05-0.07 ＝ 判定帯 ±0.10 とほぼ同じ大きさになり、関門が帯の内外を分離できない。**
n=10 にすると SE は 0.03-0.05 ＝ **帯の半分以下**になる。
**測る対象・判定量・帯・判定文はキューの登録どおりで、変えたのは n だけ。**
壁時計のスクリーン（N20 1 run = 71 秒、最も重い関数）から **50 run は 5 関数並列で 15 分以内**と見積もった。
seed は 300-309（過去のどのサイクルとも重ならない帯）。

## 4. 反証されるもの（この回が空振る条件を先に書く）
