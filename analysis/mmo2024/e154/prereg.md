**書いた時刻: 2026-09-22 00:33 UTC。採点を 1 度も走らせる前に書いた。**
**追加評価ゼロ**（保存済みダンプの再採点だけ）。**`core/` は触らない。MC-ESO の既定は変えない。腕は作らない。**

## 0. この回が撃つもの

その153 §3 が実測した食い違い ——
**この harness は 3 次元すべてで同じ手法（RR-CMA-ES）の MPR を 0.09〜0.19 低く、mean-F1 を 0.12〜0.20 高く測る。Score の一致は相殺。**
その153 が名指しした機序は**報告集合の大きさ**（競技の上限 `max(100, 2K)` に対し、この harness の `eps_loose+dedup` は 5.5〜11.3 点）。
**この回はその機序を直接検査する。**

## 1. 事前に確定させた事実（データを見る前に、公表値と `core/benchmarks.py` だけから）

**(A) この suite の競技上限は全問題・全次元で 100 点の定数である。**
K は M01-M08 が 20、M09-M16 が 10（`niching_by_name(...).n_global_optima`、3 次元とも同一）なので
`max(100, 2K) = max(100, 40 or 20) = 100`。**＝ 「上限に K が入る」ことはこの suite では一度も効かない。**
（`e115/analyze.py` の docstring が言う「cap に K を使うのは規則違反」という論点も、値としては消える。）

**(B) 公表値の (MPR, mean-F1) の対から、公表手法が実際に報告した点数を逆算できる。**
F1 = 2pr/(p+r) を p について解くと p = F1·r/(2r − F1)、報告点数 n = detected/p = (MPR·K)/p:

| D | 公表 MPR | 公表 F1 | 逆算した precision | 逆算した n（K=20） | 逆算した n（K=10） |
|---|---|---|---|---|---|
| 5 | 0.844 | 0.585 | 0.4476 | **37.7** | **18.9** |
| 10 | 0.651 | 0.565 | 0.4991 | **26.1** | **13.0** |
| 20 | 0.476 | 0.413 | 0.3647 | **26.1** | **13.1** |

**＝ 公表手法の報告点数は概ね 1.3〜1.9 × K（13〜38 点）で、上限 100 の 1/3 以下。**
**この harness の 5.5〜11.3 点はその 1/2〜1/4。** **＝ 「上限まで報告する」ではなく「1.3〜1.9K まで報告する」が競技側の実態である。**
（注: 5 水準平均の値を集計レベルで逆算しているので近似。水準ごとの n は 1 つなので誤差は F1 の凸性ぶん。）

## 2. 測るもの（すべて保存物の再採点。新規 run ゼロ）

**入力**（キュー 1 が名指しした 5 本。D=10 の RR は保存物が無い —— `e149` のダンプは その150 が削除済み）:

| D | `Restart-Lander` | RR-CMA-ES |
|---|---|---|
| 5 | `e153/descents.csv.gz` | `e153/dumps_rrcma.csv.gz` |
| 10 | `e115/descents/`（16 ファイル） | **無し**（転記値のみ ＝ 掃引できない） |
| 20 | `e151/descents.csv.gz` | `e152/dumps_rrcma.csv.gz` |

**掃引する腕**: 現行 `eps_loose+dedup`（r=0.05·span）の集合を**核**とし、
**残りの降下を `best_f` 昇順で N 点になるまで足す**（＝ 報告点数だけを動かし、核の順序は変えない）。
`N ∈ {core（足さない）, 13, 20, 26, 38, 50, 75, 100, all（全降下）}`。
**`N = core` で その153 の数値が 1 文字も変わらないことを関門にする。**

**副次の腕**（同じ再採点で取れるので一緒に出す。判定には使わない）:
間引き半径 `r/span ∈ {1e-6, 1e-4, 1e-3, 1e-2, 5e-2, 1e-1}` を Score / mean-F1 の上で掃く
（その115・その130 は**同じ半径を PR / MPR の上だけ**で掃いた。方針欄 2026-09-11 (1) が
「報告規則の項が空なのは PR の上での結論で、F1 の上では未検証」と명示した軸）。

**天井の計器**: **全降下を報告したときの MPR ＝ この harness の recall の上限**（報告規則では動かせない量）。

## 3. 判定（キュー 1 の (i)(ii)(iii) に対応）

- **(i) Score の向き**: N を上げたとき 16 問平均 Score が上がるか下がるか。
- **(ii) 内訳の食い違いが報告点数で説明できるか**: **公表値と同じ次元・同じ手法で、
  `|MPR − 公表| < 0.05` かつ `|mean-F1 − 公表| < 0.05` を同時に満たす N が存在するか。**
  照合できるのは **D=5 の RR（公表最良は RR-CMA-ES 自身、0.844 / 0.585）と D=10・D=20 の RR**（0.651 / 0.565、0.476 / 0.413）。
- **(iii) 順位の反転**: RL − RR の対差（Score）の符号が N で入れ替わるか。**入れ替われば頭の主張は報告規則に依存する。**
  検定は `e115/analyze.py` の `paired`（両側 Wilcoxon exact）をそのまま使う。**新しい統計量は定義しない。**

## 4. 予測（外れたらそう書く）

- **P1**: MPR は N について単調非減少、mean-F1 は小さい N のあと単調減少、**Score は内点で最大を取る。**
- **P2**: **(ii) を満たす N は D=5 の RR で N ≈ 26〜38 に存在する。** 根拠は §1(B) の逆算と、
  D=5 の RR の降下本数が 1 問あたり平均 26.3 本しか無いこと（＝ 公表側の報告点数とほぼ同じ桁）。
- **P3**: **順位は反転しない。** D=5 は全 N で RL が上、D=20 は全 N で帰無。
- **P4（いちばん外れやすい）**: **全降下を報告しても MPR は公表値に届かない問題が出る。**
  届かなければ**その問題の赤字は報告規則では閉じない**（探索側の被覆の不足）。

## 5. 反証条件（キュー 1 が書いたものをそのまま使う）

**どの N でも 3 次元とも内訳の食い違いが 0.05 より大きく残るなら、原因は報告点数ではない**
＝ **採点器そのものか公表値の条件の読み違いなので、`analysis/mmo2024/e92/refs/` の公表表に戻って条件を 1 行ずつ照合し直す**
（この回ではそこまでやらず、「報告点数では閉じない」と書いて次の一手に落とす）。

**もう 1 つ**: **関門（N = core が その153 の 16 問平均を ±5e-5 で再現する）が外れたら判定は出さない。**

## 6. この回でやらないこと

- **報告規則の調律ではない。** Score を上げる腕を探しているのではなく、**公表値との照合可能性を測っている。**
  掃引で Score が上がる N が出ても、**それを「採用」とは書かない**（判定 (i) は事実の記録であって採否ではない）。
- **キューの並べ替え・ゴールの変更・`status.md` の編集はしない。**
- **D=10 の RR は保存物が無いので掃引しない**（新規 run を出さない。転記値は比較先としてだけ使う）。
