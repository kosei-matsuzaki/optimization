# その151 事前登録 — キュー 1「`Restart-Lander` を D=20 で 16 問回し、公表値の D=20 行と突き合わせる」

**書いた時刻: 2026-09-21 06:34 UTC（run を投入した直後、採点前）。以後この節は書き換えない。**

## 1. 何を測るか

**`Restart-Lander`（既定 `sigma_ratio=0.1` / `descent_budget=12500`。1 ビットも変えない）を
M01-M16 / D=20 / PIN01 / seed 0 / 正規予算 `floor(50000x20)` = 100 万で 1 本ずつ = 16 run。**

**D=10 と変えたのは `--funcs` の `D10` -> `D20` だけ**（報告規則 `--report-rule current`、
採点器 `eps_loose+dedup` r=0.05*span、`niching_baseline.py` の他のフラグはすべて同一）。
**MC-ESO / NMMSO / RR-CMA-ES は回さない。`core/` は 1 行も触らない。**

**出す量は 6 つ**（新しい統計量は定義しない。`e149/analyze.py` の `score_arrays` と
`e115/analyze.py` の `rule_indices` / `score` / `paired` をそのまま import する）:
Score / MPR / mean-F1 / 報告点数 / 1e-1 被覆（`score` が返す recall の第 1 水準）/
深さ保持率（同 recall の 1e-5 ÷ 1e-1）。

## 3. 判定（事前登録）

- **主判定**: **16 問平均 Score を公表最良 D=20 の 0.4445 と比べる。**
- **反証条件 (a)**: **16 問平均 MPR が 0.3729（その93 のいちばん甘い上界）を超えたら、その93 の screen が外れている。**
  **これは頭の主張より重い** —— 同じ screen が **案 (C)（MC-ESO の一族の外に出る）の根拠**だから。**俯瞰に上げる。**
- **反証条件 (b)**: **Score が 0.4445 を下回ったら、頭の主張は「D ≦ 10 で成立する」という範囲つきで書く。**
  これは失敗ではない —— **範囲を測った論文になる。**
- **どちらも発火しない場合**（MPR ≦ 0.3729 かつ Score ≧ 0.4445）は、
  **「MPR では公表最良に届かないが Score では並ぶ」＝ 外挿どおり**と書く。

**この回で撃たないこと**: RR-CMA-ES との直接対決（キュー 2）、D=5（キュー 3）、腕の作成。
**D=10 と D=20 の対検定は撃たない** —— **問題は同じ 16 問だが評価予算も K も違うので対にならない**
（対検定はキュー 2 が **同一 D 上の 2 手法**で撃つ）。

## 4. 打ち切り規則（事前登録）

**1 サイクル 40 分の規則があるので `run.sh` に deadline 07:05 UTC を渡した**
（それを過ぎた時点で**未投入の run はスキップ**。投入済みは走り切らせる）。
**投入順は群 A（M01-M08、K=20）／群 B（M09-M16、K=10）交互**なので、
`-P 4` のどの波も **A 2 本 / B 2 本** ＝ **打ち切っても群に偏らない。**
**完走した問題だけで集計し、落ちた問題は必ず名指しで報告する。**
**16 問が揃わなかった場合、公表最良との比較は「完走した k 問の平均」であることを明記し、
k < 16 のときは主判定を確定とは書かない**（次のサイクルが残りを埋める）。

## 5. コストの見込み

**16 run × 100 万評価 ＝ 1600 万評価**（その149 の 32 run と同じ総評価数）。
**素の評価速度はこの環境で 3383 evals/s（M01、K=20）／ 5748 evals/s（M09、K=10）**＝
**評価だけで 1 run 2.9〜4.9 分**、4 並列で 4 波なのでコア競合と CMA の overhead 込みで **30〜50 分**を見込む。
**その148 の計画規則（16 問 × 1 腕 = 15-18 分）は D=10 の値**で、予算 2 倍 ＋ 1 評価が重い ＝ **2 倍以上**を見る。
