## 何が壊れているのか（キュー文の整理）

`mpr_sup` は **「着地分布の台の大きさ / K を 5 水準で平均した量」** で、その92 は
**「クラスの一員が再起動回数をいくら増やしても超えられない」厳密な上界**と書いた。
その172 は **M16 で `mpr_sup` 0.600 < `Restart-Lander` の実測 MPR 0.700** を見つけた（4 例目の同型）。
キュー 1 が挙げる候補は 3 つ:

- **(a) 有限抽選の偏り** —— 200 抽選では稀な盆地を取りこぼす。`ceiling()` の docstring 自身が
  「台に一度も着地しなければ p_j = 0 ＝ 上限は<u>下向き</u>に偏る」と書いている。
- **(b) 報告集合が着地分布の台を超える** —— 上界の定義が報告規則を覆っていない（構造的な理由）。
- **(c) 報告半径の帰属**（その130 の `r >= 0.001·span`）で近傍が別の最適に数えられている。

**この 3 つは排他ではない。** 切り分けの順序は「安い順」＝ **(b)(c) は追加評価ゼロなので先に、(a) は 400 抽選の上積みで後に**。

## 反証条件（数値を見る前に書く）

- **(A) 600 抽選で M16 の `mpr_sup` が 0.700 以上に上がるなら、破れは有限抽選の偏りであって計器の定義は無傷。**
  ＝ 上限表は「抽選本数を増やせば直る」側の問題になる。**その場合の運用則は「この suite の上限は 200 抽選では足りない」。**
- **(B) 600 抽選でも上がらず、かつ `S_RL(eps) \ S_null(eps)` が空でないなら、`mpr_sup` の定義が報告規則を覆っていない。**
  ＝ その92 §2 の「無限再起動の上界は上の反論を受けない」を書き直す必要がある。
  **[status.md](status.md) の判断に上げるだけにして、結論は勝手に差し替えない**（実行役の権限外）。
- **(C) どちらでもなければ（600 で上がらず、差集合も空）、残るのは報告半径の帰属だけ。** その130 の規則を 1 行確認して閉じる。
- **(D)（自分で足した予測 1）破れは<u>緩い水準</u>（1e-1 / 1e-2）に寄る。** 理由: 緩い水準では停止した降下が
  最近傍最適に credit されるので、台は稀な抽選 1 本で動く。**逆に差が 1e-5 にあるなら、null は<u>深い盆地</u>を取りこぼしている**
  ＝ (a) の中でも「稀」ではなく「深さ」の話になり、その171 の機序（深さ不足）が新 suite にも戻る。
- **(E)（自分で足した予測 2）200 → 600 で台が増えるのは<u>高々 1 最適</u>**（`mpr_sup` で +0.10 以内）。
  **2 最適以上増えるなら、200 抽選の上限表（その92・その94・e172 の 13 問全部）は系統的に低すぎる**
  ＝ 破れは M16 の 1 問の話ではなくなる。**この場合だけ「表の引き直しが必要」と書く。**
- **(F)（自分で足した予測 3）第 1 部で `S_RL(eps) \ S_null(eps)` が空でないとき、その credit 点の `dist` は
  同じ水準の null の着地点の `dist` 分布の中に収まる。** **外れ値（例えば `dist` が最適間距離の半分を超える）なら (c) が効いている。**
