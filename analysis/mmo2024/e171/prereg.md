## 測るもの

**最適化 run はゼロ。** `scripts/hunt_coverage.py --null` を **7 関数（N14/N15/N16/N17/N18/N19/N20）× 2 設定**で回す:

- **RL 設定**: `--sigma-ratio 0.1 --budget 12500`（＝ `Restart-Lander` の既定）
- **既定設定（対照）**: `--sigma-ratio 0.2 --budget 1499`（＝ その88・その89 の降下。**その88 の 2000 本ではなく
  同じ 600 本で引き直す** —— `--null` の抽選 k は k だけに依存するので **2 設定は抽選単位で対になる**。
  その89 が使ったのと同じ paired 構造）

**抽選本数は 600 本**（キューの指示「2000 本ではなく 500-800 本」）。7 関数すべて回す
（**枠に入らなければ N20-CF4-20D を落としてよい**とキューが明示しているが、
probe では N20 600 本が 4 プロセスで約 6 分なので入る見込み）。

**採点**: その88 §6 の手順 —— **`best_f <= 1e-5` で絞ってから** `land_opt` を数えて着地分布 p_j を作り、
**n = suite 予算 400,000 ÷ 1 降下の平均コスト**の多項抽出で 1 run 分の相異なる最適数
`sum_j [1 - (1-p_j)^n]` を出す。**実装は `analysis/mmo2024/e92/analyze.py` の `ceiling()` を import して使う**
（その92 以降のすべての次元を 1 つのコード経路で採点している関数。新しい推定量は書かない）。
**ブートストラップ 2000 回の 95% CI を併記する**（上限は有限抽選の下向き偏りを持つので、
「超えない」を主張する側には CI の上端を見る必要がある）。

  「クラス上限」の語の条件に **「上限を引いた降下が比較対象の降下と一致している」を 1 条加える**
  （status.md の判断 (2) に 1 行）。
- **(iii) 追加（自分で足す。その170 §3 の延長として測れるので）**: **CF3 の 最適 2 が
  N16-5D / N18-10D でも開く**なら、その170 が D=2/3 で見た開き方は**次元に延びる** ＝
  その88 §4 の「添字は次元によらず {2,3}」は RL の降下では成り立たない。
  **逆に 5D/10D で 0 本なら、開きは低次元だけの現象で、その170 の (ii) の読み（移植できない）が 1 段強くなる。**

  （点推定だけで「超えない」と書かない）。
