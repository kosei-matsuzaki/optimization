**5 次元 BBOB-24（F01-F24）で MC-ESO ＋ 比較 5 手法の現在地を、その177 の 2D と同じ環境・同じ手法集合で測る。**

### 実行上の逸脱 1 件（40 分枠に入れるため。値は変えていない）

**24 関数を 4 つの shard に分け、4 プロセスを並列に走らせた**（関数を交互に配って多峰の重い尾を散らした）。
- shard A: F01 / F05 / F09 / F13 / F17 / F21
- shard B: F02 / F06 / F10 / F14 / F18 / F22
- shard C: F03 / F07 / F11 / F15 / F19 / F23
- shard D: F04 / F08 / F12 / F16 / F20 / F24

**この分割は RNG 同一である** —— `core/runner.py:54` が各 run の seed を `seed=i*100`（run 番号だけ）で決めており、
**どの関数が同じプロセスに同居するかは結果を変えない**（NMMSO だけが `np.random.seed` を触るが、この回は回していない）。
`_run_dim` は関数ごとに `summary.csv` / `wilcoxon.csv` へ追記するので、**4 本の CSV の連結は 1 本で回した場合とバイト等価**（順序だけ違う）。
BLAS の oversubscription を避けるため `OMP_NUM_THREADS=1` 等を立てた。
**n_runs・関数数・手法数・予算はどれも削っていない** —— 削ったのは壁時計だけである。
理由: その177 の実測（2D・6 手法・20 run で 29.0 分）から、5D は評価数が 2.5 倍で単一プロセスでは 40 分に入らない。

## 反証条件（キューの原文。数値を見る前に固定する）

  **「高次元に伸びしろがある」というテーマ切替の前提が崩れる。** その場合は**俯瞰に上げ、キュー 2（10D）の前に止まる。**
- **(b) IPOP との差が −17pt 前後で再現すれば**、旧環境の高次元表は**方向として使える**と書ける。
- **(c) 2D と同じく「5 手法の仮想ベスト − MC-ESO」が 1pt 未満なら**、5D も比較手法から取れるものが無い次元である。

**追加で 1 つだけ先に決めておく**（後付けの読みを防ぐため）:

その177 の「24 関数でいちばん孤立した勝ち」は次元をまたぐ性質である**と書ける。**逆に 5D で崩れるなら 2D 限定の所見に留める。**
